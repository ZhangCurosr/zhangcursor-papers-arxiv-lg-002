# 论文速读：TRIAGE: Three-level Routing and Intelligent Agent Guidance for Efficient Execution

## 一句话总结
TRIAGE提出了一种三级路由框架，通过将历史执行轨迹抽象为可复用技能（TaaS），实现语义相似查询的零成本复用，在安全监控场景下实现62.3%的token节省，跨域验证达到76.3%。

## 研究问题与动机
1. **ReAct范式的根本效率缺陷**：每个查询都从头开始完整推理，相似查询（如"传感器的在线率"与"摄像机的在线率"）重复执行相同的schema推断、SQL生成、结果格式化步骤，浪费大量token。
2. **现有缓存技术仅支持精确匹配**：GPTCache等缓存系统只能处理完全相同的字符串，无法识别语义相似的查询。
3. **提示压缩/投机解码未解决重复推理问题**：LLMLingua仅压缩输入长度，Medusa仅加速生成，均未从根本上消除对相似查询的重复推理。
4. **缺乏系统性利用历史轨迹的完整框架**：虽有Reflexion、DSPy等工作，但none提供了系统性的历史轨迹复用机制。

## 核心贡献（创新点）
1. **TRIAGE三级路由框架**：实现62.3% token节省（199,782→75,238），将查询分类为直接复用（L1）、技能替换（L2）、完整ReAct（L3）三个级别，本质区别在于零成本路由而非添加推理开销。
2. **TaaS（Trajectory-as-a-Skill）范式**：将历史执行轨迹视为可复用的"技能"，实现"经验即服务"；与传统Function Calling需预定义固定模式不同，TaaS通过语义检索自动发现和执行轨迹。
3. **语义编码器驱动的检索机制**：使用all-MiniLM-L6-v2（384维）实现61.5%的L1+L2复用率，本质区别在于基于余弦相似度的语义匹配而非精确字符串匹配。
4. **自动冷启动与在线学习**：无需预训练或人工标注，系统在首次使用中自动积累轨迹和提取技能，形成"使用越多→效率越高"的正反馈循环。
5. **自动技能提取机制**：高频轨迹模式自动蒸馏为细粒度确定性技能，通过参数化模板实现零token成本执行。
6. **跨域验证（ToolBench 15域）**：76.3% token节省（424,792→100,875），证明语义路由框架的泛化性。
7. **路由策略消融发现**：阈值路由vs LLM路由的选择取决于路由开销与单查询执行成本的比值，非普适性结论。

## 方法详解
**系统架构**包含四个核心模块：
1. **语义编码器**：基于all-MiniLM-L6-v2，将查询编码为384维向量用于余弦相似度检索。
2. **相似度阈值路由器**：零成本确定性路由机制，L1阈值≥0.98，L2阈值≥0.90。
3. **轨迹检索器**：基于余弦相似度检索最相似的历史轨迹。
4. **技能提取器**：对L2候选执行确定性参数替换。

**TaaS生命周期**（Store→Retrieve→Reuse→Distill闭环）：
- **Store**：每次成功执行的查询自动存入轨迹数据库，无需手动标注。
- **Retrieve**：新查询通过语义编码器检索最相似历史轨迹。
- **Reuse**：根据相似度分发到L1（直接复用）、L2（技能替换）、L3（完整ReAct）。
- **Distill**：高频轨迹模式自动蒸馏为参数化技能，注册到全局技能注册表。

**三级路由机制**：
- **L1（直接复用）**：余弦相似度=1.0时直接返回历史结果，0 token消耗；≥0.98但<1.0时先尝试轻量级规范化，无法解决时触发LLM二次判断。
- **L2（技能替换）**：余弦相似度≥0.90时匹配已蒸馏技能，提取参数值并执行确定性替换，0 token消耗；无匹配时回退到L3。
- **L3（完整ReAct）**：余弦相似度<0.90时执行完整ReAct循环，自动存储轨迹供未来复用。

**自动技能提取流程**：
1. **模式规范化**：将工具调用中的具体值替换为类型化通配符，生成结构指纹。
2. **频率累积**：按模板键聚合，计数器达到阈值后成为提取候选。
3. **参数归纳**：通过实例间pairwise差异发现变量槽位，结合词法上下文和类型标签分配语义参数名。
4. **确定性注册**：将参数化模板注册到全局技能注册表，估计token成本为0。

**在线学习三阶段**：
- **冷启动**（query 1-50）：全L3执行，平均~197 token。
- **预热**（query 50-300）：L1/L2命中上升，L3比例降至<10%。
- **成熟**（query 300-1000）：L2稳定在56.0%，L1在5.5%，平均token成本降至74.7。

## 实验与结果
**主实验**（1,007个安全监控查询）：
- **总token**：199,782→75,238，节省62.3%
- **平均每查询**：198.4→74.7 token
- **API调用**：1,007→421次，节省58.2%
- **路由分布**：L1占5.5%，L2占56.0%，L3占38.5%
- **成功率**：三级路由均为100%

**跨域验证**（ToolBench 15个领域，345查询）：
- **总token**：424,792→100,875，平均节省76.3%
- **路由分布**：L1占84.6%，L2占11.6%，L3占3.8%
- 最高节省：love_calculator 92.2%，free_nba 89.3%
- 最低节省：chart_lyrics 56.2%，lost_ark_simple 57.9%

**在线学习实验**：
- L2命中率从0%升至57%（前100查询内）
- 平均token成本从198降至74.7

**消融实验**：
- **移除L2**：节省率从62.3%降至55.0%，证明L2是效率提升的主要驱动因素。
- **LLM路由vs阈值路由**：阈值路由节省62.3%，LLM路由净损失37.3%（路由开销225,628 token超过基线总成本），揭示路由策略选择取决于"路由开销/单查询执行成本"比值。

## 相关工作脉络
1. **GPTCache**（Fu et al., 2023）：仅支持精确字符串匹配缓存，无法处理语义相似查询；TRIAGE通过语义编码器实现模糊匹配。
2. **LLMLingua**（Jiang et al., 2023）：提示压缩方法，仅减少输入长度；TRIAGE直接消除推理循环。
3. **Medusa**（Cai et al., 2024）：投机解码加速生成；TRIAGE通过轨迹复用避免重复生成。
4. **Reflexion**（Shinn et al., 2023）：通过迭代自我反馈提升agent质量；TRIAGE关注效率优化而非质量提升。
5. **Function Calling**（传统技能系统）：需开发者预定义固定模式功能模块；TaaS自动发现和使用轨迹技能。
6. **DSPy**（Khattab et al., 2023）：将声明式调用编译为优化流水线；TRIAGE侧重经验复用而非程序优化。
7. **Toolformer/ToolBench/Gorilla**：扩展LLM工具使用能力但未解决执行效率问题；TRIAGE聚焦于减少重复推理开销。

## 局限性与未来方向
**局限性**：
1. **冷启动成本**：前10-50个查询无法从复用中获益，需完整ReAct执行。
2. **领域特异性**：轨迹无法跨领域复用，每个领域需独立积累经验和技能。
3. **首个查询低效**：第一个查询必然走L3路径，无法优化。
4. **错误传播风险**：轨迹中存在的错误可能无验证机制地传播到后续复用。

**未来方向**（论文自述）：
1. **程序合成增强技能表示**：将参数归纳升级为领域特定语言（DSL）上的归纳程序合成，支持条件分支、聚合和组合。
2. **可组合技能库与多模态工具统一**：将技能作为可动态链式调用的原语，统一SQL、REST API、GUI操作等异构工具。
3. **在线与终身技能学习**：解决技能冗余、冲突和概念漂移，避免灾难性遗忘。
4. **技能正确性验证与安全保证**：集成形式化验证、基于契约的执行或符号约束检查。
5. **对比经验提取**：当参数替换后的查询执行失败时，比较失败与成功版本推断格式转换规则。
6. **跨领域轨迹迁移与多智能体共享**：实现领域无关的轨迹抽象和质量评估。

## 研究启发与可借鉴点
1. **TaaS范式可迁移至其他重复推理场景**：代码生成、数据分析、报表生成等领域可借鉴"轨迹即技能"思想，将历史执行记录抽象为可复用模式。
2. **零成本路由设计**：阈值路由比LLM路由更高效的事实提示，在设计系统时应优先消除冗余计算而非增加复杂性。
3. **正反馈循环机制**："使用越多→效率越高"的设计模式可应用到需要持续优化的任何系统中，如推荐系统、任务规划等。
4. **三阶段演化评估框架**：冷启动→预热→成熟的在线学习曲线可作为评估类似系统的标准范式。
5. **参数化模板提取技术**：自动将高频模式蒸馏为参数化模板的方法可迁移到工作流优化、API调用优化等场景。

## 关键术语表
**TaaS（Trajectory-as-a-Skill）**：核心理念，将历史执行轨迹抽象为可复用的技能，实现"经验即服务"。
**三级路由（Three-level Routing）**：根据语义相似度将查询分类为直接复用（L1）、技能替换（L2）、完整ReAct（L3）的机制。
**语义编码器（Semantic Encoder）**：使用all-MiniLM-L6-v2将查询编码为384维向量用于相似度检索。
**自动技能提取（Automatic Skill Extraction）**：将高频轨迹模式蒸馏为参数化模板并注册到全局技能注册表的过程。
**冷启动（Cold Start）**：系统初始阶段无历史轨迹，所有查询需完整ReAct执行的时期。
**热启动（Warm-up）**：系统积累足够轨迹后，L1/L2命中上升、L3比例下降的过渡阶段。
**成熟阶段（Mature Phase）**：系统达到稳定复用率的长期运行状态，平均token成本显著低于基线。
**余弦相似度阈值（Cosine Similarity Threshold）**：L1=0.98、L2=0.90的相似度边界，用于确定查询是否可复用。
