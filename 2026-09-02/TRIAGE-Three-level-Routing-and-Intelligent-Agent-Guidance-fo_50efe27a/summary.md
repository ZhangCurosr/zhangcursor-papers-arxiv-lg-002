# 论文速读：TRIAGE: Three-level Routing and Intelligent Agent Guidance for Efficient Execution

## 一句话总结
论文提出了TRIAGE框架，通过"轨迹即技能"（TaaS）机制将历史执行轨迹抽象为可复用技能，实现三层语义路由（直接复用/技能参数替换/完整推理），在安全监控场景下减少62.3%的token消耗，跨域验证达76.3%。

## 研究问题与动机
- **核心问题**：基于ReAct范式的LLM Agent每次查询都从头开始完整推理，导致大量token浪费
- **现有方法不足1**：缓存系统仅处理精确字符串匹配，无法识别语义相似的查询
- **现有方法不足2**：提示压缩、投机解码等优化技术不消除重复推理本身
- **现有方法不足3**：传统Skill系统需开发者预定义固定模式，维护成本高且泛化能力弱
- **实证数据**：单次ReAct循环平均消耗198 tokens，1007个查询总计199,782 tokens，大量冗余

## 核心贡献（创新点）
1. **TRIAGE三层路由架构**：实现62.3% token减少，通过语义相似度阈值自动分发到三个执行层级
2. **TaaS（轨迹即技能）范式**：将历史执行轨迹抽象为可复用技能，实现"经验即服务"，区别于预定义技能的Function Calling
3. **语义编码器驱动检索**：使用all-MiniLM-L6-v2生成384维嵌入，实现61.5%的L1+L2复用率
4. **自动冷启动机制**：无需预训练或人工标注，随使用自动积累轨迹和提取技能
5. **自动技能提取机制**：高频轨迹模式自动蒸馏为细粒度确定性技能，形成"越用越高效"的正反馈循环
6. **跨域验证**：ToolBench 15个领域345个查询实现76.3% token减少，验证泛化能力
7. **路由策略分析**：消融实验揭示阈值路由与LLM路由的选择取决于路由开销与查询执行成本的比值

## 方法详解
**系统架构**：TRIAGE包含四个核心模块：语义编码器、相似度阈值路由器、轨迹检索器、技能提取器。

**TaaS生命周期**：
- Store：成功执行的查询自动追加到轨迹数据库，编码为语义嵌入索引
- Retrieve：新查询通过余弦相似度搜索检索最相似历史轨迹
- Reuse：根据相似度分数分发到三层路由
- Distill：高频轨迹模式自动蒸馏为确定性技能

**三层路由机制**：
- L1（直接复用）：相似度≥0.98，完全相同的查询返回历史结果，0 token
- L2（技能替换）：相似度≥0.90，结构化相似查询，通过技能参数替换执行，0 token
- L3（完整ReAct）：相似度<0.90，全新查询，完整LLM推理并存储轨迹

**自动技能提取**：
- 模式规范化：将具体值替换为类型化通配符，生成结构指纹
- 频率累积：模板键聚合计数，达到阈值后成为候选
- 参数归纳：通过实例间差异分析发现变量槽位，分配语义参数名
- 确定性注册：参数化模板注册到全局技能注册表，执行成本为零

**在线学习动态**：
- 冷启动阶段（1-50查询）：全L3执行，约197 tokens/查询
- 预热阶段（50-300查询）：L2命中率从0%升至57%，平均token降至74.7
- 成熟阶段（300-1000查询）：L2稳定在56.0%，L1在5.5%，L3仅38.5%

## 实验与结果
**数据集**：1,007个基于真实安全监控数据库的英语查询（15个参数化SQL模板生成947个查询，60个固定日报查询）

**基线**：完整ReAct循环，无历史经验共享

**主要结果**：
- Token总消耗：199,782 → 75,238（减少62.3%）
- 平均tokens/查询：198.4 → 74.7
- API调用：1,007 → 421（减少58.2%）
- L1+L2复用率：61.5%（564个L2 + 55个L1）

**跨域验证**（ToolBench，15个领域，345查询）：
- Token减少：424,792 → 100,875（76.3%）
- L1+L2复用率：96.2%
- 最高节省：love_calculator领域92.2%
- 最低节省：chart_lyrics领域56.2%

**消融实验**：
- 阈值路由 vs LLM路由：阈值路由62.3%节省，LLM路由-37.3%（净损失）
- 移除L2机制：节省降至55.0%，证明L2是关键驱动因素
- 执行成功率：三个层级均保持100%

## 相关工作脉络
1. **GPTCache（Fu et al., 2023）**：语义缓存系统，但仅处理精确字符串匹配，无法识别语义相似查询
2. **LLMLingua（Jiang et al., 2023）**：提示压缩技术，减少输入长度但不消除推理循环
3. **Medusa（Cai et al., 2024）**：投机解码加速生成，不解决重复推理冗余
4. **Reflexion（Shinn et al., 2023）**：通过口头强化学习改进Agent质量，但增加token消耗
5. **DSPy（Khattab et al., 2023）**：编译声明式调用为优化管道，但Skill系统需预定义固定模式
6. **ToolBench/ToolLLM（Song et al., 2024）**：扩展LLM工具使用能力，未关注执行效率

## 局限性与未来方向
**局限性**：
- 冷启动成本：前10-50个查询无法受益于复用
- 领域特异性：轨迹不能跨领域复用
- 首查询低效：第一个查询总是需要完整ReAct
- 错误传播风险：轨迹错误可能传播，缺乏验证机制

**未来方向**：
- 程序合成用于技能表示：通过归纳程序合成提升技能表达能力
- 可组合技能库与多模态工具统一：支持复杂查询的动态技能链式组合
- 在线与终身技能学习：处理技能冗余、冲突和概念漂移
- 技能正确性验证与安全保证：集成形式化验证和合约执行
- 对比经验提取用于参数格式化：自动学习自然语言到可执行格式的转换规则
- 跨领域轨迹迁移与多Agent共享：经验在不同领域和Agent间共享

## 研究启发与可借鉴点
1. **零成本路由设计**：阈值路由在结构化查询场景中优于LLM路由，避免了额外推理开销；对高成本任务可考虑混合策略
2. **"经验即服务"范式**：将历史轨迹自动蒸馏为可复用技能，形成自我强化的效率循环，可迁移到其他需要模式识别的场景
3. **参数化技能提取框架**：规范化→累积→归纳→注册的四级抽象流程可应用于其他结构化查询语言（如NoSQL、图查询）
4. **在线学习三阶段演化**：冷启动→预热→成熟的模式设计为长期部署的系统提供了清晰的性能预期曲线
5. **跨域验证方法论**：在SQL场景外验证路由机制的泛化能力，76.3%的节省证明了语义检索的普适价值

## 关键术语表
**TaaS（Trajectory-as-a-Skill）**：将历史执行轨迹抽象为可复用技能的新范式，区别于预定义功能的Function Calling
**三层路由**：基于语义相似度的分发机制，将查询分为直接复用、技能替换、完整推理三个层级
**相似度阈值路由器**：零token消耗的确定性路由组件，使用余弦相似度阈值分类查询
**Skill提取**：从高频轨迹模式中自动蒸馏参数化模板的过程，生成零成本确定性执行器
**在线学习动态**：系统随使用逐渐积累经验的三阶段演化过程（冷启动→预热→成熟）
**参数归纳**：通过实例间差异分析发现变量槽位并分配语义参数名的技能提取步骤
**交叉领域验证**：在ToolBench的15个不同领域验证TRIAGE泛化能力的实验
**正向反馈循环**：使用越多→轨迹越多→技能越多→节省越多→更多使用的自我强化机制
