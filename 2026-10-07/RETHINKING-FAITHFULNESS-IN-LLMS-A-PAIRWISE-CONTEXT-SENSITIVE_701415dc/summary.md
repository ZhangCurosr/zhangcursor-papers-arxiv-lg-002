# 论文速读：RETHINKING-FAITHFULNESS-IN-LLMS-A-PAIRWISE-CONTEXT-SENSITIVE

## 一句话总结
本文提出配对忠实度基准 PFaithBench，通过固定问题、改变上下文充分性来评估 LLM 在"回答"与"拒绝"之间的上下文敏感切换能力；发现现有模型普遍存在过度回答偏见，且该现象与内部参数知识泄漏密切相关。

## 研究问题与动机
- **现有评估缺陷**：当前忠实度评测在独立实例上分别评估"充分上下文下回答正确"与"不充分上下文下拒绝"，混淆了问题变化与上下文变化的影响，无法直接度量模型是否具备"同问题下随上下文切换行为"的能力。
- **核心能力缺口**：在 RAG 等依赖外部上下文的场景中，忠实性不仅要求回答正确，还要求模型在证据不足时能够拒绝回答；过度回答会导致幻觉，过度拒绝则降低可用性。
- **训练数据效应不明**：已有工作大多聚焦单一上下文字段，系统研究训练数据中"回答数据 vs 拒绝数据"配比、以及充分/不充分上下文耦合方式如何影响模型切换行为的实证研究仍然缺失。
- **可迁移的评测范式需求**：需要一种能同时覆盖多跳推理、单跳阅读、反事实上下文等多样化语境，且能统一衡量过度回答与过度拒绝的基准。

## 核心贡献（创新点）
- **提出 PFaithBench 配对忠实度基准**：为同一问题构造充分上下文 $c^+$ 与不充分上下文 $c^-$ 的配对，使评测能够直接衡量"答案—拒绝"切换能力，而不是分散独立评估。
- **定义两类主要忠实度误差并识别普遍过度回答偏见**：将错误分解为 Over-answering（上下文不足仍回答）与 Over-abstention（上下文充分却拒绝），并在 39 个模型（7 个模型族）的系统评测中发现绝大多数模型倾向于过度回答。
- **量化内部参数知识泄漏并揭示其与过度回答的关系**：提出 Leakage = P(y⁻=C) 指标，测量模型在上下文不足时依赖内部知识的概率；分析显示越大的模型往往泄漏越高，说明过度回答部分来源于参数化知识的回退。
- **开展数据中心的配对忠实度训练分析**：系统探究上下文耦合方式与回答/拒绝数据配比两个因素对 GFPO 训练效果的影响，揭示"错配耦合导致数据集特定捷径"与"回答—拒绝数据不平衡导致行为极端化"两个规律。

## 方法详解
- **问题设定**：每个样本为 $(q, c^+, c^-, a)$，其中 $c^+$ 包含足够证据、$c^-$ 仅通过最小化修改关键信息使证据不足；模型对 $y^+ \sim \pi_\theta(\cdot|q,c^+)$ 应正确回答，对 $y^- \sim \pi_\theta(\cdot|q,c^-)$ 应拒绝（IDK）。
- **响应分类与基本指标**：将响应分为 IDK（拒绝）、C（正确）、W（错误），由此定义：
  - **OverAns = P(y⁻ ∈ {C,W})**，反映不足上下文下仍回答的倾向；
  - **OverAbs = P(y⁺ = IDK)**，反映充分上下文下拒绝的倾向；
  - **Leakage = P(y⁻ = C)**，度量在上下文不足时仍给出参考答案的比例（内部知识依赖）。
- **配对忠实度精度**：
  - **DFAcc = P(y⁺ ∈ {C,W}, y⁻ = IDK)**，衡量“是否做了正确的切换”，不要求答案正确；
  - **SFAcc = P(y⁺ = C, y⁻ = IDK)**，要求在正确切换的同时答案正确，是更严格的指标；
  - **Gap = DFAcc − SFAcc** 反映仅做对切换但答案仍错误的幅度。
- **边际精度指标**：AnsAcc = P(y⁺=C) 与 AbsAcc = P(y⁻=IDK)，用于刻画单情境表现及两者失衡（Imbalance = |AnsAcc − AbsAcc|）与强弱-严格配对偏差（Asymmetry）。
- **PFaithBench 构建**：
  - 多跳事实 QA：取自 HotpotQA 与 2WikiMultiHopQA，利用标注支持事实，将支持段落替换为无关段落构造 $c^-$，形成 **PFB-MultiHop**（1000 样本）。
  - 单跳事实 QA：取自 SQuAD，使用 LLM 改写删除/模糊关键答案支撑信息并由人工校验，形成 **PFB-SingleHop**（762 样本，保留率 76.2%）。
  - 反事实 QA：取自 ConFiQA，保留原始/反事实两组充分上下文分别构造不充分版本，形成 **PFB-ConOri** 与 **PFB-ConCF** 各 791 样本（保留率 79.1%）。
  - 总计 3344 条评测样本与约 3997 条训练样本；响应由 Qwen3-30B-A3B-Instruct-2507 作为 LLM judge 分为 {IDK, C, W}。
- **忠实度训练方案**：以 GRPO 为基础，采用区分充分/不充分上下文的奖励设计（非对称版），$c^-$ 下 IDK 得 +1、回答得 -1；$c^+$ 下正确答案 +1、错误 0、拒绝 -1（更严格惩罚拒绝），从而鼓励“充分时回答、不足时拒绝”的切换；论文同时报告了对称奖励的稳健性实验。

## 实验与结果
- **评测覆盖**：39 个模型、7 个模型族（Llama3、Qwen3、Qwen3.5、Qwen3.6、Gemma、Phi、Olmo），参数量 0.6B–70B，均采用统一 system prompt 要求仅基于提供上下文作答，并显式指示在证据不足时输出 "I don't know"。
- **主要发现一（过度回答主导）**：35/39 的模型 OverAns 显著高于 OverAbs，说明普遍存在“在上下文不足时仍尝试作答”的倾向；仅在 Olmo 系列观察到以 Over-abstention 为主的例外。
- **主要发现二（内部知识泄漏普遍）**：所有模型在 $c^-$ 下均呈现一定比例 Leakage；多数模型族中 leakage 随规模增大而上升，说明大模型更易回退到参数化知识而非拒绝。
- **主要发现三（边际强不等于配对强）**：多模型存在 AnsAcc 与 AbsAcc 的不平衡，且 DFAcc/SFAcc 明显低于各自边际表现；Gap 普遍较大，说明单侧优化不能保证“同问题切换”能力。
- **代表数值**：
  - Llama-3.1-70B/3.3-70B：OverAbs 较低（~7–10%），但 OverAns 仍在 29–33% 左右；SFAcc 约 49–50%，Gap 约 11–12%。
  - Qwen3 NoThink 系列：Mid/小尺寸在 AbsAcc 上表现较强，但部分 NoThink 模型在单跳子集上 OverAns 仍较高。
  - Qwen3 Think 系列：OverAbs 普遍很低（1–5%），但伴随更强的 OverAns（40–85%），说明开启推理会加剧“尽量作答”倾向。
  - Qwen3.5-9B Think：在 PFB-MultiHop 上 DFAcc 达 63.1%、SFAcc 55.3%，Gap 10.35%，为多跳场景表现较好的代表之一。
  - 模型族均值（Table 9）：Llama 族 OverAns 平均 36.41%、OverAbs 19.48%；Qwen3.5 NoThink 族 SFAcc 达 45.47%、Leakage 最低 8.80%。
- **训练数据效应**：
  - **上下文耦合**：错配耦合（如 MHSuff-SHInsuff / SHSuff-MHInsuff）会导致模型依赖数据源线索而非上下文充分性；同一来源配对（PairContext）在多数设置中获得最佳 DFAcc/SFAcc 并最小化 |OverAns − OverAbs| 与 |AnsAcc − AbsAcc|。
  - **回答—拒绝配比**：以 $\alpha$ 表示回答数据比例，$\alpha=0$ 导致严重 Over-abstention（SFAcc 趋近 0），$\alpha=100$ 导致极端 Over-answering（部分模型 OverAns 接近 100%）；在 $\alpha \approx 50$ 附近 DFAcc/SFAcc 达到峰值，表明平衡数据组合最有利于切换能力。
  - **通用能力**：在 AMC、AIME24/25、MATH500、MMLU-Pro、GPQA-Diamond、IFEval 上的评测表明，忠实度训练对数学推理、知识问答与指令遵循等通用能力影响较小，性能总体与基线相当。

## 相关工作脉络
- **FaithEval、RGB、ClashEval、ContextDPO、TimeQA** 等基准多采用实例级独立评测，分别关注不可答、含噪、知识-上下文冲突、时间敏感等设置；本文与它们在范式上的本质差异是**控制性问题固定**，直接测量“同问题不同充分性下的行为切换”。
- **RA-DIT、RAFT** 等上下文感知微调方法侧重于让模型更贴合给定上下文生成答案，但未显式建模“证据不足时应拒绝”的行为，也未在配对设置中评估。
- **R-Tuning、Alignment for Honesty、CanAISayNo** 等拒绝意识训练工作主要面向开放生成或通用对话的拒答对齐；本文将其置于**配对上下文对比**的严格评测中，揭示这些方法在切换一致性上的潜在盲区。
- **ContextDPO、FaithRL、KnowRL、Faithfulness-Aware Step-Level RL** 等偏好/强化学习路线在特定上下文条件上优化行为；本文指出此类方法通常训练-评测分离，难以捕捉模型在 $c^+$/$c^-$ 之间切换能力的真实分布。
- **时间敏感与反事实 QA 研究**（如 TimeQA、ConFiQA）多为独立设置；本文通过构造原语境与反事实语境各自的充分/不充分版本，统一纳入同一配对基准，便于对比不同语义类型的切换难度。

## 局限性与未来方向
- **配对构造依赖人工/改写质量**：单跳与反事实子集采用 LLM 改写加人工校验，可能存在改写强度、语义漂移或人工主观性带来的偏差；多跳通过段落替换构造，替换方式也可能影响难度梯度。
- **评测范围与语言偏置**：当前主要基于英文 QA 数据集，跨语言与多模态场景的配对忠实度尚未系统评估。
- **训练方案以 GRPO 为主**：主要结论建立在单一奖励设计与一种对齐算法上；不同 reward 形状、策略优化方法与更大规模训练条件下的普适性需进一步验证。
- **规模效应并非单调改善**：结果并未显示单纯扩大模型规模即可系统性降低 OverAns 或 Gap，表明当前主流训练目标（尤其 outcome-based RLVR）可能内在地偏向过度作答，需要新的目标/约束。
- **未来方向**：可扩展至多语言、多任务与多模态；探索更鲁棒的上下文耦合训练与动态配比策略；从目标函数层面抑制参数知识对不充分上下文的回退（如显式分离参数/检索信号）。

## 研究启发与可借鉴点
- **配对评测范式值得迁移**：在需要“条件切换行为”的任何能力（如不确定性校准、置信控制、拒绝式决策）中，固定对象+扰动条件的配对评测比独立分位数评测更能揭示系统性偏差。
- **上下文耦合应保持一致**：训练数据中充分/不充分上下文的来源分布必须与评测分布对齐，否则模型易学会基于数据源 cue 走捷径；建议将“来源配对一致性”作为数据质检的硬约束。
- **回答—拒绝数据要显式平衡**：单一方向的数据放大（无论是增加证据充分样本还是增加不可答样本）都会带来行为极端化；采用居中配比（如约 50/50）并在多个粒度验证 DFAcc/SFAcc 双指标更为稳妥。
- **通用能力不应被牺牲**：本文在数学、知识与指令遵循上的评估表明，忠实度训练可与通用能力训练并行；建议在后续工作中将此类多任务基准作为硬约束加入训练回路。
- **内部知识泄漏可作为辅助正则信号**：Leakage 指标揭示了过度回答的一部分来源，可在奖励中引入对“不足上下文下仍输出与训练分布高度一致的参数化答案”的抑制项。

## 关键术语表
- **Pairwise Faithfulness（配对忠实度）**：对同一问题在充分与不充分两个配对上下文上，测量模型能否正确在“回答”与“拒绝”之间切换的性质。
- **Over-answering（过度回答）**：在上下文不足以支持答案时，模型仍给出实质性回答的错误行为。
- **Over-abstention（过度拒绝）**：在上下文充分时，模型仍选择拒绝回答（输出 IDK）的错误行为。
- **Internal knowledge leakage（内部知识泄漏）**：模型在上下文不足时仍利用自身参数化知识给出参考答案的概率。
- **DFAcc / SFAcc**：Decision Faithfulness Accuracy 与 Strict Faithfulness Accuracy，前者只要求切换正确，后者额外要求充分上下文下的答案正确。
- **Gap（DFAcc − SFAcc）**：反映模型在做出正确切换判断的同时仍未能给出正确答案的幅度。
- **PFaithBench**：本文提出的配对忠实度基准，包含 PFB-MultiHop、PFB-SingleHop、PFB-ConOri、PFB-ConCF 四个子集，共 3344 条评测样本。
- **PairContext / Mismatched coupling**：前者指充分与不充分上下文保持同问题配对分布；后者指两者来自不同来源，可能引发基于数据源捷径的学习。

## 可复现要素
- **数据集**：PFaithBench 已开源，地址 https://github.com/tmlr-group/PFaithBench；评测来源于 HotpotQA、2WikiMultiHopQA、SQuAD、ConFiQA，训练样本约 3997 条，评测样本 3344 条。
- **代码/权重**：论文声明代码与数据已发布；未提供额外模型权重的单独下载链接。
- **关键超参与设置**：统一 system prompt 要求仅基于上下文作答并在不足时输出 "I don't know"；温度 1.0、top-p 0.9；响应由 Qwen3-30B-A3B-Instruct-2507 作为 LLM judge；训练基于 GRPO，使用非对称或对称奖励；回答数据占比 $\alpha \in \{0,25,50,75,100\}$；评测与训练脚本细节见附录。
