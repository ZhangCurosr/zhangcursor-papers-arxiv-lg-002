# 论文速读：SSR-Sparse-Segment-Reduction-for-Ternary-GEMM-Acceleration

## 一句话总结
本文提出稀疏段归约（Sparse Segment Reduction，SSR）算法，通过构造仅含非全零模式的紧凑计算树，在推理阶段消除冗余加法并降低内存流量，使三元 GEMM 在稀疏度超过 50% 时具备渐近更快的理论复杂度。实测 SSR 在 Llama‑3‑1B 推理上较 RSR++ 提速 3.5–6.3×，内存节省 4.9%。

## 研究问题与动机
- **三元 LLM / TWN 普遍高稀疏**：实际模型稀疏度常达 50%–95%，但现有三元推理方法（BitNet、RSR/RSR++）在算法层面未利用该稀疏结构，仍对零权重执行运算。
- **通用稀疏 GEMM 无法适配三元特性**：CSR/JDS/COO 等格式面向科学计算设计，未考虑三元权重只有 {−1,0,+1} 且可通过 `W=W₁−W₂` 拆分为两个二进制矩阵的特殊性，错失双重优化机会。
- **已有三元专用算法存在冗余传输**：RSR++ 虽通过冗余段归约降低了理论复杂度，但仍会传送完整的置换数组、对不影响输出的元素进行计算，且内存访问呈非线性，损害缓存性能。
- **硬件优化需求迫切**：边缘侧部署受计算与内存带宽限制，亟需可在 CPU/GPU 上运行且独立于特定硬件架构的三元 GEMM 加速方案。

## 核心贡献（创新点）
- **提出 SSR 三元稀疏 GEMM 框架**：先离线预处理权重生成“缩减置换序列 + 分段序列”，推理时仅对非全零行求和并按递归树合并，本质区别在于把零权重连同对应的索引一并剔除，而非 RSR++ 那样保留后再归约。
- **渐近复杂度优于 RSR++（稀疏度 p>50%）**：每行每块有效操作数由 K 降至 K−E[全零行数]，当 p>0.5 时指数项 −1/log₂(1−p) < 1，理论上比 RSR++ 更高阶低；RSR++ 在 p=0.5 处与之收敛。
- **专用紧凑数据格式节省内存**：删除全零行索引后，置换数组与分段列表均缩短，初始化内存最多减少 15.1%，推理期动态内存减少 9.6%–17.8%。
- **完整 CPU 工程实现与多层级评估**：支持循环展开、AVX2 SIMD 与多线程，分别在 GEMM 级、Llama‑MLP 块级、Llama‑3‑1B 端到端三个粒度验证，最高 GEMM 加速 11.3×，端到端加速 6.3×。
- **给出块大小 L 的经验选择规律**：最优 L 随稀疏度升高而减小、随矩阵维度增大而增大，且须满足 L < log₂N，为后续硬件自适应调参提供依据。

## 方法详解
- **权重拆解**：三元矩阵 W∈{−1,0,+1}^{K×N} 拆成两个二进制矩阵 W₁、W₂，满足 W=W₁−W₂，随后对两个二进制矩阵分别执行相同预处理。
- **列阻塞（Column Blocking）**：按块宽 L 把列切分为 Wᵢ⁽ᴸ⁾，末块可能少于 L 列。
- **置换序列（Permutation Sequence）**：把每块内行向量当作 L 位二进制数解释为整数键 κᵢ(r)，对行按 κ 升序排列得到置换 σᵢ。
- **缩减置换序列**：统计块内全零行数 q，去掉 σᵢ 前 q 个对应全零模式的索引，得到 σ′ᵢ，从而把零权重行彻底剔除。
- **分段序列（Segmentation List）**：对排序后的块统计每种非零模式（共 2ᴸ−1 种）的累计出现次数，得到边界列表 sᵢ={b₀,…,b_{2ᴸ−1}}，相邻边界之差即该模式的行数。
- **分段求和（Segmented Sum）**：推理时按 σ′ᵢ 把激活行 xⱼ 的对应元素按模式分组求和，产出向量 uᵢ（长度 2ᴸ−1）。
- **树计算（Tree Computation）**：以 uᵢ 为 v₀，递归取 v_ℓ 下标 ≥2 的偶数位构成 v_{ℓ+1}，直至长度为 1；再将各层 v_ℓ 的偶数位求和按逆序拼接，得到块输出 zᵢ。该过程等价于按二进制位逐层折叠相加。
- **复杂度推导**：设零权重出现概率为 p，则 E[全零行数]=pᴸ·K，块内加法由 K 降至 K−pᴸ·K；取 L=⌈log₂K/log₂(1/(1−p))⌉ 可使 SSR 运算量上界低于 RSR++ 的 2MNK/(log₂K−1)。

## 实验与结果
- **平台与实现**：AMD Ryzen 7 8845HS，Windows 11，MSVC v143；C++ 实现，开启循环展开、AVX2 SIMD 与多线程。
- **GEMM 级**：激活 512×1024，权重 1024×4096，L=6。单线程优化 SSR 较 RSR++ 快 4.9–20.2×（稀疏度 45%–95%）；多线程 AVX2 版本较 RSR++ 快 2.1–11.3×，较 PyTorch Sparse CSC 快最高 59.4%。
- **MLP 块级（Llama‑3‑1B）**：SSR 较 RSR++ 快 1.8–7.5×，较 PyTorch CSC 快最高 38.5%；初始化内存减少 5.4%–15.1%，推理期动态内存减少 9.6%–17.8%。
- **端到端（Llama‑3.1‑1B，seq=512）**：RSR++ 延迟在 50%–90% 稀疏度下几乎不变（~36.2 s），SSR 从 10.49 s（50%）降至 5.71 s（90%），相对 RSR++ 加速 3.45–6.34×，总内存 2960 MB vs 3113 MB（−4.9%）。
- **最强结果**：三元 GEMM 在 95% 稀疏度下获得 11.3× 加速；端到端推理在 90% 稀疏度下获得 6.34× 加速。

## 相关工作脉络
- **BitNet / BitNet.cpp**：用查找表加速三元 GEMM，但未剔除全零模式，内存与计算仍有冗余；SSR 在此基础上进一步去掉零模式并缩短索引结构。
- **RSR / RSR++**：通过冗余段归约把三元 GEMM 降到对数级，但置换数组仍含全零行、内存访问非线性；SSR 的差别在于预处理阶段直接删除全零行，使后续树计算与数据传输同步缩小。
- **T‑MAC**：利用查找表实现 4–5× 加速，侧重硬件可查表化；SSR 与硬件无关，可同样在 CPU/GPU 部署。
- **通用稀疏库（Eigen/PyTorch Sparse CSR/CSC）**：面向科学计算格式，在稀疏度 ≤90% 时甚至比密集 GEMM 更慢；SSR 针对三元结构重新组织数据，在中低稀疏度下同样有效。
- **低比特量化设施（FP8/FP6/FP4）**：通过降低精度压缩模型，但与三元特有稀疏结构正交；SSR 可与这些量化手段叠加使用。
- **硬件加速器（FPGA/Tensor Core 稀疏三元算子）**：提供低层算子优化，但算法层面的冗余去除仍需依赖格式创新；SSR 的树形归约结构可直接映射至向量/并行硬件。

## 局限性与未来方向
- 目前仅在 CPU 上做系统评测，GPU 实现与调优尚未完成。
- 实验中块大小 L 采用固定值，未引入基于性能画像的动态选择机制。
- 仅评估 Llama‑3/3.1‑1B，未覆盖其他开源三元 LLM 或不同层结构（如 MoE、卷积主干）。
- 注意力层未做三元化，端到端加速受限于非稀疏部分占比。
- 理论分析假设权重元素独立以零概率 p 出现，实际训练分布可能存在相关性。

## 研究启发与可借鉴点
- **把“全零模式剔除”融入归约类算法**：凡涉及按位模式分组再折叠的算法（如 RSR 族、查找表族），均可在预处理阶段先剔除全零索引，从而同时压缩内存与计算量。
- **块大小 L 的经验规律可迁移**：稀疏度越高 L 越小、矩阵越大 L 越大，这一调参直觉可推广至其他基于列块划分的低比特 GEMM 优化。
- **树形偶数位递归合并可作通用原语**：SSR 的 tree computation 本质上是一次位感知的流式归约，可抽象成独立算子复用于其他二进制/三元归约场景。
- **多层级评测设计值得借鉴**：从 GEMM→MLP 块→端到端三级验证既揭示算子收益，也暴露非三元部分的瓶颈，可作为类似系统论文的评测模板。
- **INT8 基准对比提示实现质量差异**：论文中 INT8 版 Eigen/PyTorch 显著慢于 FP32，提醒我们在做低比特加速对比时需优先保证基线实现已充分优化，否则结论易被反常噪声干扰。

## 关键术语表
- **三元 GEMM**：激活为稠密实数矩阵、权重仅取 {−1,0,+1} 的矩阵乘法，是三元 LLM/TWN 推理的核心算子。
- **缩减置换序列 σ′ᵢ**：对列块内行按二进制键升序排列并剔除全零行后得到的行索引子序列。
- **分段序列 sᵢ**：记录排序后块中每种非零二进制模式累计边界位置的数组，相邻差值即为该模式出现次数。
- **树计算**：递归抽取偶数位并求和的折叠过程，最终把各层偶数位和逆序拼接成块输出。
- **渐近优于 RSR++ 的阈值**：当稀疏度 p>0.5 时，SSR 的指数项 −1/log₂(1−p)<1，运算量阶低于 RSR++。
- **时间到首 Token（TTFT）**：端到端评测指标，衡量从输入到模型输出首个 token 的延迟。
- **W=W₁−W₂ 分解**：将三元权重拆成两个二进制矩阵，使后续二值归约与符号相减解耦。
- **块大小 L**：列阻塞宽度，平衡模式空间大小（2ᴸ）与归约深度的超参数，经验上应小于 log₂N。

## 可复现要素
- **代码**：已开源，链接 https://github.com/fpgasystems/ternaryLLM。
- **数据集/模型**：使用 Llama‑3‑1B / Llama‑3.1‑1B 的 MLP 块与完整推理管线，模型为开源权重。
- **硬件平台**：AMD Ryzen 7 8845HS @3.8GHz，Windows 11，MSVC v143。
- **关键超参**：块大小 L 在 GEMM 实验取 4/6，MLP 与端到端实验取 6；单次实验重复 10 次取平均。
- **精度说明**：主结果基于 FP32；INT8 版本的 PyTorch/Eigen 基线性能异常，论文已剔除其主要对比，仅保留参考值。
