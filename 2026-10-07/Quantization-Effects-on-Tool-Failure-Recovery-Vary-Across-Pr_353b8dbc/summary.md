# 论文速读：Quantization-Effects-on-Tool-Failure-Recovery-Vary-Across-Pr

## 一句话总结
本文系统评估了 8-bit 与 4-bit 量化对 Llama-3.1-8B-Instruct 和 Qwen2.5-7B-Instruct 在工具瞬态故障恢复行为上的影响，发现不存在模型无关的精度优势，且结论随提示词、评估目标（分开筛选/匹配任务/全流水线）和评分策略（宽松/严格）而变化，甚至在某一设置下出现方向反转。

## 研究问题与动机
- 部署压缩 Agent 不仅要求任务完成率，还要求在工具暂时不可用时能合理重试、不捏造答案、在恢复后完成任务。
- 已有量化 Agent 评估主要报告任务完成，缺少对可控工具故障恢复行为的比较。
- 故障注入实验常只在"被测配置清洁通过"的任务上注入故障，若每次配置单独筛选清洁任务集，比较可能混合了任务选择差异与真实恢复差异。
- 评估目标（分开筛选 vs. 匹配任务 vs. 全流水线）与评分政策（宽松解析 vs. 严格输出合约）均可改变 8-bit/4-bit 比较的符号，需要明确报告以避免误导性结论。

## 核心贡献（创新点）
1. 提出面向压缩 Agent 的工具瞬态故障恢复比较实验，并系统性对比不同评估目标与评分策略下的结论差异。
2. 发现 8-bit 并不在模型与提示上保持一致的恢复优势，Qwen 的 8-bit–4-bit 差异在不同提示下可从 −50.0 点变到 +35.0 点。
3. 揭示严格评分可使 Llama/P4 的全流水线 8-bit 优势 (+28.3 点) 反转为 4-bit 优势 (−15.0 点)，说明输出修复本身应被计入评估系统。
4. 给出可复用的三个评估目标与不确定性估计方案，并提供公开日志支持重评分与复现。

## 方法详解
- **任务与环境**：20 个确定性订单管理任务（10 个含订单/客户/折扣查询，10 个额外含运费查询），值由固定种子生成，每个任务有验证过的答案与最小轨迹；附录含 40 题的多订单与干扰工具族。
- **模型与量化**：Llama-3.1-8B-Instruct 在 Q8_0、Q4_K_M、Q3_K_M；Qwen2.5-7B-Instruct 在 Q8_0、Q4_K_M；用 llama.cpp 全 GPU 卸载、temperature=0、top-k=1、固定种子，运行于 NVIDIA L4。
- **故障设定**：沿黄金工具路径在每个有效站点注入瞬态故障 ET：一次目标调用失败，后续相同调用成功；共 13–50 个故障片段/提示-精度单元。
- **提示词**：P0 含工具签名、每轮一对象格式、工作示例、工具可能失败且可重试、report_failure；P1/P2 为叙述体，P3 为编号规则，P4 为简短祈使；非对照改写，P3/P4 在早期结果后编写。
- **三种评估目标**：
  - 分开筛选：在 S(a,p) 上平均 r_{a,p}(t)。
  - 匹配任务：在 S(a1,p)∩S(a2,p) 上比较，隔离同任务恢复差异。
  - 全流水线：在所有 20 任务上平均，清洁失败计 0，适合部署决策 ranking。
- **两种评分策略**：宽松容忍非 JSON 首对象提取与算术表达式求值；严格要求全程 JSON 与字面数值；清洁筛选与重评分使用同一执行器。
- **不确定性估计**：以任务为单元，采用 20,000 次 bootstrap；不同清洁集比较用两样本 bootstrap，固定任务比较用配对 bootstrap 与双侧符号检验；主对比报任务均值与 95% CI。

## 实验与结果
- **匹配任务 recovery**：Llama 8-bit–4-bit 差异在 P0 为 +20.2 点（CI [4.8, 39.3]），P1 +3.9，P2 +4.4，P3 +4.2，P4 0；仅 P0 排除 0。Qwen 为 +8.3、−3.3、−10.0、−50.0（CI [−65.0, −35.0]）、+35.0（CI [20.0, 50.0]），P3/P4 反向排除 0，证伪单一精度优势。
- **全流水线**：Llama 在所有提示上 8-bit 点估计更高；Qwen 为 +33.3、−1.7、−8.3、−28.3、+17.5，符号随提示变化。
- **分开筛选的误导**：Llama/P4 分开筛选 favor 4-bit 17.5 点，但 8-bit 清洁通过 19 题、4-bit 仅 10 题，结论由分母不同驱动；匹配 9 题恰为 0，全流水线 favor 8-bit 28.3 点。
- **评分策略反转**：严格评分下 Llama/P4 分离筛选 −17.5→−42.9，匹配 −33.3，全流水线 +28.3→−15.0；Qwen 几乎不变（仅 1/165 片段提交表达式）。说明输出修复依赖可作为 8-bit 优势的虚假来源。
- **最强结果**：全流水线 + 宽松评分下，Llama/P0 的 8-bit 优势最大 (+27.5 点，CI [12.5, 44.2])；Qwen/P3 的 4-bit 优势最大 (−50.0 点)。

## 相关工作脉络
- ACBench 评估压缩 Agent 的通用能力，但未隔离可控瞬态工具故障下的恢复行为；本文补位这一空白并展示其评估设计如何改变结论。
- ToolMaze 提供故障分类与恢复框架，但仅评估全精度 Agent；本文将其与量化比较结合。
- τ²-bench 表明聚合分数可掩盖量化诱导故障；本文进一步指出即便在聚合比较之外，筛选目标与评分政策也会改变跨精度排名。
- Brittlebench 研究提示鲁棒性；本文提示改写非对照语料扰动，关注部署指令差异而非语言鲁棒。
- DARC 等恢复 harness 若用于模型变体比较，需要同样的匹配任务与任务级不确定度。
- GPTQ/k-bit 缩放律研究量化可行性；本文强调部署可靠性还需考虑外部故障与执行合约。

## 局限性与未来方向
- 仅 20 个任务、单一合成环境与两相似规模模型，泛化到其它领域/家族/尺度不足。
- 多提示非对照改写，P3/P4 在早期结果后编写，无法确立单因子因果机制。
- 全提示交集仅含 9 个 Llama/3 个 Qwen 任务，存在明显天花板效应。
- 故障模型仅含单次瞬态失败与重复相同调用，缺少反复失败、退避、限流与状态变化。
- Q8_0/Q4_K_M/Q3_K_M 为 GGUF 预设，结论适用于预设而非位宽本身；Qwen 未测 3-bit。
- 严格评分仅重评分日志，未重跑推理，模型若被告知表达式被拒可能行为不同。

## 研究启发与可借鉴点
- 评估压缩 Agent 时应同时报告匹配任务 recovery（条件比较）与全流水线 success（部署决策），并明确说明评分政策。
- 以任务为不确定性单位，避免把同一任务的多次注入站点当作独立样本；公开 episode 日志支持事后重评分。
- 输出修复（宽松解析、表达式求值）应视为被评估系统的一部分；当不同精度对修复的依赖差异大时，宽松/严格两套结果同报。
- 提示改写若含多特征变化，不适合归因；需要单因子 ablation（如仅改重试次数阈值）。
- 将"清洁通过率差异 + 恢复差异"解耦，是识别虚假精度优势的关键思路，可迁移到压缩/蒸馏/微调对比。

## 关键术语表
- **Post-training quantization (PTQ)**：训练后对权重/激活进行低比特量化以降低存储与计算成本。
- **Tool-failure recovery**：Agent 在工具短暂不可用后重试或正确终止并以恢复方式完成任务的行为。
- **Transient fault (ET)**：单次调用失败、后续相同调用成功的临时故障。
- **Separately screened recovery**：分别在各自清洁通过任务集上评估的恢复率，分母可能不同。
- **Matched-task recovery**：在两精度均清洁通过的任务交集上评估的恢复率。
- **Full-pipeline success**：全任务集上平均，清洁失败计 0，反映"先认证再故障"的门控部署流程。
- **Tolerant vs. strict scoring**：前者允许非 JSON 提取与算术表达式，后者要求全程 JSON 与字面数值。
- **Task-level bootstrap**：以任务为抽样单元的 bootstrap，避免将同任务多次注入站点当作独立证据。
