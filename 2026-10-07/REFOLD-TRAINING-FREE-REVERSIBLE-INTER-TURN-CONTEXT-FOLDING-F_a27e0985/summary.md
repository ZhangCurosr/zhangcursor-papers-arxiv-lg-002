# 论文速读：REFOLD-TRAINING-FREE-REVERSIBLE-INTER-TURN-CONTEXT-FOLDING-F

## 一句话总结
本文提出 **ReFold**，一种无需训练的上下文渲染层，通过在渲染阶段对长视界 LLM 代理的历史交互进行**去重（Deduplication）**和**折叠（Folding）**，在保持原始追加写入历史完整性的前提下，将模型实际看到的上下文压缩，同时保证所有删除操作严格可逆，从而在不增加额外模型调用、不破坏前缀缓存的情况下显著降低 token 消耗与 KV-cache 内存占用，且不损害任务成功率。

## 研究问题与动机
1. **长视界代理上下文增长失控**：基于 ReAct 范式的代理在每一步都会将完整的追加写入交互历史重新发送给模型，导致上下文长度与推理成本随步数线性甚至二次增长，极易超出模型上下文窗口。
2. **现有上下文管理方法存在系统性缺陷**：主流策略（如位置驱逐、内容裁剪、外部存储、摘要压缩）通常需要额外的模型调用或启发式规则，会引入运行时开销、破坏前缀缓存（Prefix Cache）复用，且一旦丢弃信息往往无法恢复，造成潜在的信息永久丢失。
3. **仅裁剪工具输出无法保证上下文有界**：实证表明，只压缩工具观测结果（Tool Outputs）并不能控制代理自身指令与推理轨迹的累积，系统提示与任务描述等固定开销仍会占用大量预算，导致上下文超限率依然很高。
4. **生产环境中的成本与延迟瓶颈**：在大规模部署中，触发上下文压缩的会话虽占少数，却贡献了绝大部分 Token 消耗；同时，频繁的上下文修改会引发缓存失效与请求排队，严重拖慢推理速度。

## 核心贡献（创新点）
1. **提出一种位于渲染层的免训练压缩框架 ReFold**：与已有方法通过辅助预测器或摘要模型来修改历史不同，ReFold 仅改变发送给模型的上下文视图，底层交互历史保持不变，完全避免了额外模型调用与训练依赖。
2. **设计两种定向的上下文渲染操作：去重与折叠**：去重通过 Span 匹配消除历史观测中的完全重复内容，替换为轻量的引用 Stub；折叠则利用代理自行报告完成的步骤（STALE 标记）将整个轮次压缩为一行摘要 Note，两者均直接作用于渲染后的上下文。
3. **通过分块渲染（Chunked Rendering）与严格可逆性设计规避系统性成本**：两种操作共享一个每 k 步才前进一步的边界，使得缓存前缀在块内保持不变，大幅减少前缀缓存失效；任何删除均可通过 `restore <step>` 命令从原始历史精确恢复，消除了信息永久丢失的风险。
4. **系统评估六种基线并验证 ReFold 的综合优势**：在统一 harness 下对比了 Mask、Prune、Recall、Compact 等策略，证明仅裁剪工具输出不足以保证上下文有界，且辅助操作会带来显著开销；在五个长视界基准（SWE‑bench 系列、Terminal‑Bench）与两个前沿模型（Qwen3.6‑27B、Qwen3.6‑35B‑A3B）上的实验显示，ReFold 可将 Token 消耗降低 18%–60%，单次会话峰值 KV‑cache 内存减半，且在受限上下文预算与高并发服务场景下能减少最多 92% 的强制压缩、最高 100% 的请求排队延迟，推理加速达 1.7 倍、成本降低 3.4 倍，同时任务解决率未下降。

## 方法详解
**整体架构**：ReFold 作为 mini‑swe‑agent（一个 ReAct‑style 框架）的渲染插件运行，不修改代理的工具、环境或交互协议，仅通过一个渲染钩子（Render Hook）与提示词修改实现。

**形式化设定**：设交互历史为 $\mathbf{h}_t = \mathbf{p}_{\text{sys}} \oplus \mathbf{p}_{\text{task}} \oplus \bigoplus_{i=1}^{t} \mathbf{z}_i$，其中 $\mathbf{z}_i = \mathbf{a}_i \oplus \mathbf{o}_i$ 为第 $i$ 轮代理动作与环境观测。默认情况下模型输入 $\mathbf{c}_{t-1} = \mathbf{h}_{t-1}$，上下文量随步数 $T$ 以 $\Theta(T^2)$ 增长。ReFold 引入渲染函数 $R$，将历史映射为压缩上下文 $\mathbf{c}_t = R(\mathbf{h}_t)$，而历史本身不被修改。

**上下文渲染操作**：
- **去重（Deduplication）**：将观测 $\mathbf{o}_i$ 划分为连续 Span $\{s_{i,\ell}\}$，若某 Span 与之前某轮完全相同，则将其替换为引用 Stub，Stub 记录被省略的内容来源步骤，并保留顶级类/函数签名。例如：`[context‑manager] <path>:<start>‑<end> omitted: identical to step <source step>. \`restore <step>\` shows it again.`
- **折叠（Folding）**：通过提示词要求代理在每个响应开头输出两个元数据字段：`PROGRESS`（一行描述当前步骤做什么）和 `STALE`（代理认为不再需要读取其输出的早期步骤索引集合 $\langle \text{STALE}_t \rangle$）。ReFold 仅接受最近 $k$ 步内的 STALE 索引（$S_t = S_{t-1} \cup (\text{STALE}_t \cap \{t‑k,\dots,t‑1\})$）。对于每个 $i \in S_t$，将整个轮次 $\mathbf{z}_i$ 替换为一行摘要 Note：`[context‑manager] steps <i>‑<j> folded: <PROGRESS_i> · … · <PROGRESS_j> \`restore <i>‑<j>\` shows them again.` 若提取到函数签名或搜索结果等关键细节，则附加在 Note 下方。

**分块渲染与可逆性**：
- 两种操作共享一个边界 $b_t = \max\!\bigl(0,\; k\lfloor (t‑k)/k \rfloor \bigr)$，每 $k$ 步前进一步（实验中 $k=3$）。边界之后的轮次完整渲染；边界之前且标记为 STALE 的轮次折叠；其余轮次去重。在边界前进之间，渲染上下文保持严格追加写入，从而保护前缀缓存。
- 可逆性通过两种方式实现：① 代理可发出 `restore <step>` 命令，执行 harness 会直接从原始历史查找该轮并追加为新轮次，不修改已有上下文；② 代理可重新执行原始命令，由于文件未变，输出完全相同，且重新执行得到的观测不再受压缩处理。

**提示词修改**：在系统提示中追加一段说明，告知代理 `[context‑manager]` 标记是 harness 记账而非 shell 错误，并解释 `restore` 命令的用法；将原有响应格式要求替换为必须包含 `PROGRESS` 和 `STALE` 两行；为每轮工具输出添加 `[step N]` 标签以便引用；若代理遗漏元数据字段，则在最新观测后附加强制提醒。

## 实验与结果
**数据集与基线**：在五个长视界基准上各取 50 个任务：SWE‑bench Verified、SWE‑bench Pro、Multi‑SWE‑bench（多语言软件仓库修复）、Terminal‑Bench 1.0 与 2.1（终端任务）。使用 Qwen3.6‑27B（稠密）与 Qwen3.6‑35B‑A3B（MoE）两个模型，均通过 vLLM 在双 GPU 上服务，开启前缀缓存。基线包括 base（无压缩）、compact（到达上下文 75% 时触发摘要压缩），并与之前消融研究中对比的 mask、prune、recall 等策略共同组成动机实验。

**主要结果**：
- **任务成功率**：在完整 256k 上下文窗口与 $w=8$ 并发下，ReFold 的解决任务数与 base 相差 ±1～±3（在运行随机性范围内），五个基准均未出现显著下降。
- **Token 与成本**：Qwen3.6‑27B 上 Token 消耗降低 18%～53%，成本降低 2%～35%；Qwen3.6‑35B‑A3B 上 Token 降低 42%～60%，成本降低 18%～45%。
- **内存与效率**：单次会话峰值 KV‑cache 内存减半（30%～58%），平均任务步数减少最多 40%（例如 Terminal‑Bench 2.1 上从 42 步降至 29 步）。
- **受限上下文预算**：在 24k、32k、64k 预算下，ReFold 使 compaction 事件减少高达 92%（32k 时从平均 1.0 次降至 0.1 次），平均成本降低 24%～36%，中位时长降低 12%～17%；即使 16k 的极紧预算下，compaction 仍减少 33%。
- **高并发服务**：在 $w=48$ 时，ReFold 将解任务数从 7 提升至 32，队列延迟从 8.96 s 降至 0.02 s；在 $w=64$ 时，队列延迟从 42.2 s 降至 23.1 s，解任务数从 18 提升至 39。整体推理加速最高 1.7 倍，成本降低最高 3.4 倍。

**消融实验**：
- **分块大小 $k$**：峰值 KV‑cache 与中位时长在 $k=3\sim5$ 时最低，选取 $k=3$ 以平衡压缩率与缓存命中率。
- **分块渲染效果**：不开分块时前缀缓存命中率仅 51%，开启后维持在 87%（base 为 84%）。
- **可逆性效果**：关闭 restore 后，约三分之一被丢弃的观测 Token 无法恢复（与 compact 相当）；开启时所有删除均可精确还原。
- **去重与折叠贡献**：折叠单独即可降低 49% 的 KV‑cache 与 50% 的 Token，去重单独贡献较小，两者叠加达到最佳压缩效果（KV‑cache 降低 52%）。

## 相关工作脉络
1. **上下文裁剪与驱逐**：如 mask（仅保留最近 N 轮观测）、prune（用 0.6B 分类器筛除无关行）、recall（将观测移至外部地址存储器）等方法只作用于工具输出，无法控制代理自身消息的累积，且往往不可恢复或破坏前缀缓存。
2. **摘要压缩**：Claude Code、Codex 等商业系统在上下文接近阈值时调用额外模型调用生成摘要，并永久丢弃原始历史；CompactionRL、SWE‑MeM 等学习何时以及如何摘要的策略则需要离线训练与适配。
3. **可检索外部记忆**：MemGPT、LCM、ARC 等将历史存入外部存储，代理通过显式命令召回，虽可恢复但增加了交互复杂度与调度延迟。
4. **Token 级压缩**：LLMLingua‑2 通过困惑度过滤压缩提示，但会降低缓存命中且不可逆；SkipKV 在 KV 缓存层面跳过部分键值，属于系统级优化而非上下文管理。
5. **ReFold 的定位**：与上述方法不同，ReFold 完全免训练、无需辅助模型调用，通过代理自我报告的完成信号（STALE）与内容重复检测实现压缩，且所有删除均可逆，同时采用分块渲染保护前缀缓存，在降低资源消耗的同时维持甚至提升任务成功率与系统吞吐量。

## 局限性与未来方向
- **依赖代理遵循特定提示格式**：折叠操作要求代理在每个响应开头输出 PROGRESS 和 STALE 字段，若代理不严格遵守则效果下降；未来可探索更鲁棒的自动检测机制或自适应提示策略。
- **去重与折叠的保守性**：目前仅处理完全重复的 Span 与代理明确声明的 STALE 步骤，可能遗漏部分语义冗余；可结合语义相似性检测与更细粒度的关键信息提取进一步提升压缩率。
- **分块大小需根据场景调优**：$k$ 值影响缓存命中率与压缩频率，当前固定为 3，未来可设计动态调整策略以适应不同长度的任务轨迹。
- **仅验证了代码代理场景**：实验集中在软件 engineering 与终端任务，对于多模态代理、长文档分析等其他长视界场景的适用性尚未验证。
- **未与所有最新方法直接对比**：部分近期工作（如 AgentFold、ACON）在相同 harness 上的直接比较仍待补充；未来可将其作为更强的基线进行更全面评测。

## 研究启发与可借鉴点
1. **渲染层压缩思想**：将上下文压缩移至渲染层而非修改历史，既能保持历史完整性，又避免引入额外计算开销，该设计可迁移至多模态代理、长文档处理等场景。
2. **分块渲染保护前缀缓存**：通过共享边界、定期批量更新而非每步修改历史，有效维持 KV 缓存命中，这一机制对任何基于前缀缓存的推理系统均有参考价值。
3. **代理自我报告完成信号**：利用代理自身标记的 STALE 字段识别可折叠步骤，无需外部预测器，既准确又零开销，可推广至其他需要识别“子任务完成”的代理工作流。
4. **可逆删除保证信息不丢失**：通过 `restore` 命令从原始历史精确恢复，消除了压缩带来的信息永久丢失风险，适用于医疗、法律等对回溯性要求极高的领域。
5. **统一 harness 下的系统评估**：在相同 harness、相同任务集上公平对比六种策略，清晰揭示了各方法的系统性成本（运行时开销、缓存失效、不可恢复性），为后续研究提供了可靠的实验范式。

## 关键术语表
- **ReFold**：一种无需训练的上下文渲染层，通过在渲染时对长视界代理的历史进行去重与折叠来压缩模型实际看到的上下文，同时保持原始历史不变且所有删除可逆。
- **Deduplication（去重）**：将历史观测中完全重复的内容替换为轻量的引用 Stub，Stub 指向首次出现的位置并保留关键签名。
- **Folding（折叠）**：将代理已报告为完成（STALE）的整个轮次压缩为一行摘要 Note，Note 中包含该轮次的 PROGRESS 描述与提取的关键细节。
- **Chunked Rendering（分块渲染）**：去重与折叠共享一个每 $k$ 步前进一步的全局边界，边界后的轮次完整渲染，边界前的轮次按需压缩，从而在块内保持上下文追加写入特性以保护前缀缓存。
- **Reversibility（可逆性）**：任何被删除的内容均可通过 `restore <step>` 命令从原始追加写入历史中精确恢复，或直接重新执行原命令获得最新状态。
- **STALE / PROGRESS**：由代理在每次响应开头输出的两个元数据字段，STALE 列出代理认为不再需要其输出的早期步骤索引，PROGRESS 用一句话描述当前步骤的工作内容。
- **KV‑cache（键值缓存）**：现代 LLM 推理引擎（如 vLLM）缓存已计算的键值对以避免重复计算，前缀缓存命中可显著降低推理延迟与显存占用。
- **Context Compaction（上下文压缩）**：当上下文接近窗口限制时，通过摘要、裁剪或驱逐等手段缩减上下文长度的过程；ReFold 通过分块渲染与可逆删除大幅减少了此类强制压缩的发生。
